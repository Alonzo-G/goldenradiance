# Golden Radiance 深度优化方案

> 版本：v1.0（待用户确认）
> 日期：2026-10-08
> 性质：生产态站点增量优化（非推倒重建）
> 现状基线：1014 真实 SKU · 2 产品线（不锈钢钛钢 610 + 时尚合金 404）· 完整 RFQ/邮件/搜索链路

---

## 0. 现状诊断结论（为什么这么优化）

| 维度 | 现状 | 问题 |
|------|------|------|
| 页面结构 | 20 页，首页 6 section，结构完整 | 首页缺「使用场景」与「核心产品优势」两个转化关键板块 |
| 转化路径 | Hero → Stats → Lines → Showcase → Buyers → Compliance | 路径线性但缺「场景 → 产品」的桥接，买家无法快速定位「我的需求该看哪条线」 |
| 产品线呈现 | 2 线（steel/alloy），产品线页信息完整 | 两条线的差异化卖点（耐久 vs 时尚走量）只在产品线页，首页没有提炼 |
| 移动端 | 有 hamburger + viewport + theme-color，响应式基本可用 | RFQ 抽屉无手势、移动导航是纯列表无快捷转化、触控目标未统一校验 |
| 图片 | 主图 800/1200px + 缩略 360px，有 srcset/lazy/显式尺寸 | 缩略图 360px 在 DPR2 手机上偏糊，缺 medium 档；主图尺寸不统一 |
| 性能 | 有 lazy + fetchpriority + decoding async | 移动端图片档位不足，首屏 LCP 与字体加载可再压 |

---

## 1. 转化路径重构（P0，最高价值）

### 1.1 首页叙事顺序重构

**当前**：Hero → Stats → Lines → Showcase → Buyers → Compliance

**优化后**：Hero → **使用场景** → Stats → Lines（强化差异卖点）→ Showcase → **核心产品优势** → Buyers（如何下单）→ Compliance

新增两个板块，都是转化关键：

**① 「使用场景」板块（新增 `HomeScenarios`）**
把 2 条产品线映射到买家真实经营场景，让买家 30 秒内定位「我的货该选哪条线」：

| 场景 | 对应产品线 | 一句话卖点 |
|------|-----------|-----------|
| 日常耐戴 / 健身 / 海边 / 敏感肌 | 不锈钢钛钢 | 316L 医用钢 + PVD 镀层，抗氯抗汗不褪色，可戴可洗澡 |
| 时尚走量 / 快周转 / 低价铺货 | 时尚合金黄铜 | 款式广度最大、落地成本最低，逐款标注镀层工艺与厚度 |

每个场景卡直接链到对应产品线页（`/product-lines/stainless-titanium-steel/` 等），形成「场景 → 产品线 → 产品」的转化闭环。

**② 「核心产品优势」板块（新增 `HomeAdvantages`）**
把散落在合规页/产品线页的卖点集中提炼为 4 条可扫描的优势，每条带数据或事实支撑（诚实红线：只用已确认的事实，不编数字）：

- 真实工厂货源（三厂家直采，图片文件名即厂家编号，可溯源）
- 规格随报价确认（不虚标，材质/镀层/尺寸/重量全部随报价给出）
- 镍释放合规（EN 1811 测试标准，耳针款可测）
- 小批量起订（12–120 pcs MOQ，支持打样）

### 1.2 RFQ 转化触点增强

- 首页「使用场景」「产品优势」板块尾部各放一个 RFQ CTA，缩短转化路径
- 移动端新增**底部常驻 RFQ 快捷条**（见 §3.2），让 RFQ 入口在移动端拇指可达

## 2. 内容呈现重构（P1）

### 2.1 产品线差异化卖点提炼

两条线各提炼一个「一句话定位 + 三个差异化事实」，放在产品线页 Hero 下方与首页对应板块：

- **不锈钢钛钢线**：定位「耐用场景首选」；事实 = 316L vs 304 分级、PVD vs 水电镀、氯/汗抗性
- **时尚合金黄铜线**：定位「款式广度 + 低成本」；事实 = 锌合金/黄铜基材、镀层逐款标注、风格标签覆盖

### 2.2 产品列表页「使用场景」筛选项

现有筛选只有 品类/材质/镀层/MOQ/合规。**新增「使用场景」维度**（日常耐戴 / 时尚走量），把 `style_tags` 已有标签聚合映射到场景，让买家按场景筛货。

### 2.3 产品详情页（PDP）信息架构

- 移动端图片画廊改**横向滑动**（当前逐图显示，改左右滑 + 指示点）
- 规格区「随报价确认」降级文案统一，加「Add to RFQ」为第一主 CTA

## 3. 移动端深度适配（P0，用户明确要求）

### 3.1 导航优化

- 移动 hamburger 菜单从「纯链接列表」升级为**分组菜单**（产品线 / 目录 / 支持 / 关于），加图标与触控间距
- 菜单展开加**下滑关闭**手势

### 3.2 底部常驻 RFQ 快捷条（移动端转化核心）

移动端（<768px）新增底部 fixed 条：**「Request a Quote」+ RFQ 计数徽标**，拇指可达，点击打开 RFQ 抽屉。这是 B2B 询盘转化在移动端最关键的一处——当前移动端 RFQ 入口只在 Header 右上角，滚动后不可见。

### 3.3 交互手势

- RFQ 抽屉：移动端改**底部抽屉（bottom sheet）**，加**下滑关闭**手势（当前是右侧抽屉 + 仅 Esc 关闭，移动端不友好）
- 产品详情图廊：左右滑切换
- 移动菜单：下滑关闭

### 3.4 触控目标统一

校验所有可点元素触控区 ≥ 44×44px（iOS HIG / Android Material 标准），筛选复选框、分页、关闭按钮等小目标加大。

### 3.5 加载性能

- **图片档位补齐**：缩略图从单档 360px 增至 360/640 两档，`srcset` 加 `640w`，解决 DPR2 手机（逻辑 320px × 2 = 640 物理 px）列表卡模糊
- **首屏 LCP 优化**：Hero 首图已 `fetchpriority=high`，补 `preload` 字体与首图；`theme-color` 已设
- **移动端懒加载边界**：移动端可视区外图片延后加载（当前全局 lazy 已够，微调 `sizes` 让移动端选更小档）
- 主图尺寸归一：800px 与 1200px 混用 → 统一按产品线/用途归一，减少浏览器选图误差

### 3.6 视觉统一

- 移动端断点复核：确认 640/768/1024 三断点在主流手机（320–430px 宽）下无横向溢出
- 底部快捷条与既有深墨玉绿 `--color-accent` 主题一致，不引入新配色

## 5. 执行计划（专家团分工）

| Phase | 动作 | 负责 |
|-------|------|------|
| 确认 | 用户确认本方案 | 用户（唯一交互点） |
| Spec | 锁定页面清单 + Token + 文案 + 验收标准 | 我（项目总监） |
| 设计 | 新增板块视觉 + 移动端底部条/抽屉手势原型 | 颜好看（设计师） |
| 开发 | 前端组件 + 移动端交互 + 图片管线 | 贾思敏（前端）+ 高见远（架构，图片管线） |
| 测试 | 移动端真机尺寸 + 手势 + 性能回归 | 严过关（QA） |
| 部署 | 构建验证 + 部署 + 线上回归 | 卜宕机（运维） |

> 说明：本方案为**增量优化**，不新增 API、不改数据库 schema、不改核心询盘/邮件链路，符合「小改」边界——确认后可直接进入开发，无需回退 Phase 0 重走全流程。
