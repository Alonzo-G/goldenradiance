# 深度优化任务指令 v2

> 用法：填写 §0 输入槽后整段发送。任一槽位缺失时，执行者须先提问补齐，不得自行假设后开工。
> 适用范围：代码 / 文档 / 提示词 / 配置数据 —— 由 §0「对象类型」决定诊断口径与验收方式，一套模板覆盖。

---

## 0. 输入槽（缺任一项即停并提问）

| 槽位 | 填写内容 |
|------|----------|
| 优化对象 | 粘贴全文 / 文件路径 / 代码块 |
| 对象类型 | 代码 \| 文档 \| 提示词 \| 配置或数据 \| 其他 |
| 优化目标 | 按优先级排序、可多选：性能 \| 可读性 \| 结构 \| 算法效率 \| 正确性 \| 提示词质量 |
| 硬约束 | 例：不得新增依赖；对外接口签名不变；单文件 ≤ 300 行；产物体积 ≤ N KB；字数 ≤ N |
| 成功判据 | 可测量观测项与目标值，例：构建耗时 p95 ≤ 8s、单文件行数 ≤ 300、去重率 ≥ 40% |

---

## 1. 对象与目标界定

1. **复述边界**：说明本次优化包含什么、明确不含什么。对象由调用方给定，执行者只做复述与校验，**不得代为重新定义**。
2. **指标化**：把每个优化目标翻译成可测量指标，给出「当前基线值 → 目标值」。确实无法量化的目标，须显式标注为定性目标。
3. **不做范围**：列出本次明确不动的内容，用于防止顺手重写与范围蔓延。

## 2. 现状诊断（证据锚定，逐条）

| 编号 | 问题 | 证据：位置 + 可观测现象或数据 | 影响的目标 | 严重度 |
|------|------|-------------------------------|------------|--------|
| P1 | … | 文件:行 / 段落号 + 现象或测量值 | 性能 / 可读性 / … | P0/P1/P2 |

禁止无证据的主观评论（如「可读性差」「不够优雅」）。每条问题都必须能指向具体位置与可观测事实。

## 3. 瓶颈定位

- 指出**真正的瓶颈**，并说明定位依据：测量数据 / 复杂度分析 / 依赖关系推导。
- 明确列出「即使修复也不会改善目标指标」的问题并说明排除理由 —— 避免无效优化。

## 4. 优化方案

| 编号 | 改动 | 具体做法（含关键片段） | 对应问题 | 预期收益（可测） | 代价 | 风险 | 回退方式 |
|------|------|------------------------|----------|------------------|------|------|----------|
| O1 | … | … | P1 | 指标从 a → b | … | … | … |

按「收益 ÷ 代价」降序排列，逐项标注 **建议采纳 / 暂缓 / 不采纳** 及理由。

## 5. 约束保持与等价性证据

- 逐条对照 §0 硬约束，说明本方案如何满足。
- 给出「行为不变」的**证据**，而非宣称：改写前后对外可观测行为的对照（测试通过 / 输出比对 / 接口签名一致 / 生效范围一致）。
- 若某处属**有意改变**，单独标注并说明原因与影响面。

## 6. 输出（分两段交付）

- **A 决策版**：§1–§5 的分析、方案表与建议 —— 供确认「要不要做、做哪几项」。
- **B 成品版**：优化后的完整内容，可直接替换使用，末尾附变更清单（编号对应 §4）。
- 如需对比，另附 diff 或 before/after 对照。

## 7. 交付前自检清单

- [ ] §0 无缺项，或缺失项已提问补齐
- [ ] 每条问题都有「位置 + 现象/数据」证据
- [ ] 瓶颈已定位，非瓶颈项已显式排除
- [ ] 每条方案都有可测收益、代价、风险、回退方式
- [ ] 无未声明的行为变化；所有有意改变均已标注
- [ ] 未越出「不做范围」
- [ ] §0 硬约束逐条满足
- [ ] 成品版可直接使用或独立跑通

## 变更清单（v2 相对 v1）

| 编号 | 改动 | 解决的问题 |
|------|------|-----------|
| C1 | 新增 §0 输入槽，缺项即停并提问 | 对象缺位导致指令不可执行（原 v1 的根本缺陷） |
| C2 | 「明确对象与目标」改为复述 + 指标化，责任留在调用方 | 原 v1 把定义对象的责任推给执行者，会诱发臆断 |
| C3 | 目标从开放枚举「如…或…」改为受控多选 + 优先级排序 | 不同执行者自选维度导致结果不可复现 |
| C4 | 每条问题强制「位置 + 现象/数据 + 影响指标 + 严重度」 | 形容词型要求无法验收，易用主观评论充数 |
| C5 | 新增 §3 瓶颈定位与非瓶颈排除 | 避免把力气花在非瓶颈上（80/20 失效） |
| C6 | 方案表增列 代价 / 风险 / 回退方式，并按收益÷代价排序 | 原 v1 只谈收益不谈代价，诱导过度优化且不可撤销 |
| C7 | 新增「不做范围」 | 防止顺手重写引发范围蔓延 |
| C8 | 「保持原有功能」改为可证伪的等价性证据 | 原 v1 该约束无法验证，沦为宣称 |
| C9 | 交付拆为「决策版 + 成品版」，支持附 diff | 原 v1「方案」与「完整结果」边界重叠，交付形态不明 |
| C10 | 新增 §7 交付前自检清单 | 把质量要求门禁化，可人工或机器复核 |
